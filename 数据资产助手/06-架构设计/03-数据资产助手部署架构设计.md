# 03 数据资产助手部署架构设计

## 1. 设计目标

本文档用于说明数据资产助手在公司内部测试环境、生产环境中的部署方式，以及与现有数据资产管理平台、公司内网大模型、可观测平台的分环境对接关系。

部署架构重点回答以下问题：

1. 数据资产助手服务部署在哪里。
2. 测试环境和生产环境如何隔离。
3. 生产正式接口在核心网时，助手如何访问。
4. 大模型、可观测平台如何按环境接入。
5. Demo、联调、正式投产之间如何平滑演进。

## 2. 当前环境约束

| 约束项 | 说明 | 对助手设计的影响 |
| --- | --- | --- |
| 公司内部有测试环境和生产环境 | 两套环境都需要部署助手侧服务 | 需要按环境维护配置、密钥、模型地址、观测地址、数据库连接 |
| 正式接口在生产环境 | 现有正式 Gateway、Java API、ES、Activiti、Oracle / GoldenDB 主要在生产环境 | 生产助手调用正式接口，测试助手默认不直接调用生产正式接口 |
| 正式接口部署在核心网 | 生产能力有网络边界和访问控制 | 助手生产服务需要通过受控网络策略访问核心网接口 |
| 测试环境仅用于测试和联调 | 测试环境不能代表完整生产数据、权限和接口能力 | Demo 阶段优先使用 Gateway Mock、Mock Tool、测试数据、受控联调接口 |
| 大模型有测试和生产环境 | 内网私有化大模型按环境部署 | 测试助手调用测试大模型，生产助手调用生产大模型 |
| 可观测平台有测试和生产环境 | 公司可观测平台基于 OpenTelemetry 封装，并使用 Langfuse | Trace、Prompt、LLM 调用、Tool 调用日志必须进入对应环境的可观测平台 |

## 3. 总体部署分区

### 3.1 测试环境

测试环境用于 Demo、功能验证、联调验证和灰度前验收。

建议部署组件：

| 组件 | 部署建议 | 说明 |
| --- | --- | --- |
| 数据资产助手 AI 服务 | 测试环境部署 | FastAPI + LangGraph + LangChain Core + Tool Adapter |
| Gateway Mock / 测试 Gateway | 测试环境部署 | Demo 阶段可先使用 Mock，后续切换为测试 Gateway |
| Mock Tool / 测试 Tool | 测试环境部署 | 模拟数据地图、血缘、安全扫描、数据标准等接口 |
| 助手库表 | 测试 GoldenDB 或测试库 Schema | 保存会话、确认记录、任务状态、偏好记忆 |
| Redis | 测试 Redis | 保存短期会话状态、LangGraph Checkpoint、待确认上下文 |
| 测试大模型 | 测试模型环境 | 用于提示词、Tool Calling、结构化输出验证 |
| 测试可观测 | 测试 OpenTelemetry / Langfuse | 记录测试 Trace、评估数据、Prompt 调优记录 |

测试环境原则：

1. 默认不直接调用生产核心网正式接口。
2. 如确需联调生产正式接口，必须通过受控白名单、生产 Gateway、只读或低风险接口策略执行。
3. 测试环境禁止误写生产数据。
4. 测试环境使用独立的模型配置、观测项目、数据库 Schema、Redis Namespace。
5. 测试数据、Mock 数据、生产脱敏样本需要明确标识来源。

### 3.2 生产环境

生产环境用于正式用户访问和真实业务办理。

建议部署组件：

| 组件 | 部署建议 | 说明 |
| --- | --- | --- |
| 数据资产助手 AI 服务 | 生产服务区部署，具备访问核心网接口的受控通道 | FastAPI + LangGraph + LangChain Core + Tool Adapter |
| 现有数据资产 Gateway | 生产核心网或现有生产访问区 | 统一登录、Token 获取、用户身份透传、权限边界 |
| 现有 Java API | 生产核心网 | 数据地图、数据源、血缘、标准、安全扫描、流程等既有能力 |
| ES 数据地图搜索引擎 | 生产核心网 | 元数据采集后进入 ES，用于提升数据地图检索速度 |
| Oracle / GoldenDB | 生产核心网 | 数据资产管理平台后端数据库，当前 Oracle 迁移 GoldenDB |
| Activiti 流程引擎 | 生产核心网 | 元数据治理等场景提交流程实例 |
| 助手库表 | 生产 GoldenDB 或独立助手库 | 保存助手会话、任务、记忆、确认、审计映射 |
| Redis | 生产 Redis | 保存运行态、Checkpoint、短期上下文 |
| 生产大模型 | 生产模型环境 | 支撑正式问答、Tool Calling、结构化生成 |
| 生产可观测 | 生产 OpenTelemetry / Langfuse | 记录正式链路 Trace、模型调用、Tool 调用、异常排查数据 |

生产环境原则：

1. 用户从现有数据资产管理平台入口进入。
2. 通过现有 Gateway 登录接口获取 Token，并向助手服务透传用户身份。
3. 助手服务调用 Tool Adapter，Tool Adapter 再调用现有 Java API。
4. 正式业务写操作必须保留用户确认、流程提交、审计记录。
5. 内网登录密码、Token、敏感字段在进入可观测平台前必须脱敏。
6. 生产助手只连接生产大模型、生产可观测、生产 Redis、生产助手库表。

## 4. 环境隔离策略

| 隔离对象 | 测试环境 | 生产环境 | 隔离要求 |
| --- | --- | --- | --- |
| 服务地址 | 测试域名 / 测试网关 | 生产域名 / 生产网关 | 通过环境变量或配置中心区分 |
| 大模型 | 测试模型 Endpoint | 生产模型 Endpoint | 禁止测试请求误发生产模型 |
| 可观测 | 测试 Langfuse Project | 生产 Langfuse Project | Trace、Prompt、评估数据分环境 |
| 数据库 | 测试助手库表 | 生产助手库表 | 库、Schema 或租户标识隔离 |
| Redis | 测试 Redis / Namespace | 生产 Redis / Namespace | Key 前缀按环境隔离 |
| Tool 接口 | Mock / 测试接口 / 受控联调接口 | 生产 Java API | 测试默认不直连生产正式接口 |
| 密钥 | 测试密钥 | 生产密钥 | 密钥分环境托管，禁止混用 |
| 审计 | 测试审计 | 生产审计 | 生产审计必须可追溯到用户身份和流程实例 |

建议引入统一环境配置：

```yaml
env: test | prod
gateway:
  base_url: ${GATEWAY_BASE_URL}
llm:
  endpoint: ${LLM_ENDPOINT}
observability:
  otel_endpoint: ${OTEL_EXPORTER_OTLP_ENDPOINT}
  langfuse_project: ${LANGFUSE_PROJECT}
assistant_db:
  dsn: ${ASSISTANT_DB_DSN}
redis:
  url: ${REDIS_URL}
  key_prefix: data_asset_assistant:${ENV}:
tool:
  mode: mock | test | prod
```

## 5. 调用链路设计

### 5.1 测试链路

```text
测试用户
  -> 测试入口 / Gateway Mock
  -> 数据资产助手测试服务
  -> LangGraph 编排
  -> LangChain Core 模型与 Tool Calling 适配
  -> Mock Tool / 测试 Tool
  -> 测试数据 / 测试接口
```

旁路能力：

1. 助手测试服务调用测试大模型。
2. 助手测试服务写入测试 Redis 和测试助手库表。
3. OpenTelemetry Trace 上报到测试可观测平台。
4. Langfuse 记录测试 Prompt、LLM 调用、Tool 调用、评估数据。

### 5.2 生产链路

```text
正式用户
  -> 现有数据资产管理平台
  -> 现有生产 Gateway
  -> 数据资产助手生产服务
  -> LangGraph 编排
  -> LangChain Core 模型与 Tool Calling 适配
  -> Tool Adapter
  -> 生产 Java API
  -> ES / Oracle / GoldenDB / Activiti
```

旁路能力：

1. 助手生产服务调用生产大模型。
2. 助手生产服务写入生产 Redis 和生产助手库表。
3. OpenTelemetry Trace 上报到生产可观测平台。
4. Langfuse 记录生产 Prompt、LLM 调用、Tool 调用、异常和评估数据。
5. 写操作通过 Activiti 流程引擎落地，并保留用户确认与审计记录。

## 6. 核心网访问设计

生产正式接口部署在核心网，因此数据资产助手生产服务需要采用受控访问方式。

建议策略：

| 策略 | 建议 |
| --- | --- |
| 网络访问 | 生产助手服务通过生产 Gateway 或受控服务网关访问核心网 Java API |
| 接口白名单 | 仅开放助手需要调用的数据地图、数据源、血缘、标准、安全扫描、流程接口 |
| 身份透传 | 使用 Gateway 登录 Token 和用户身份，避免助手绕过平台身份体系 |
| 写操作控制 | 发起治理、流程提交、安全等级确认等操作必须有人机确认 |
| 数据脱敏 | 账号、密码、Token、敏感字段进入日志和观测前脱敏 |
| 降级策略 | 核心网接口不可用时，助手返回可解释的失败原因和下一步建议 |

## 7. 发布与演进路径

### 阶段 1：Demo 验证

目标：验证 LangGraph 编排、Tool Calling、元数据治理流程、可观测链路。

部署方式：

1. 测试环境部署 FastAPI 数据资产助手服务。
2. 使用 Gateway Mock。
3. 使用 Mock Tool 和 Mock 数据。
4. 接入测试大模型。
5. 接入测试 OpenTelemetry / Langfuse。

### 阶段 2：测试联调

目标：接入真实测试接口或受控联调接口，验证端到端链路。

部署方式：

1. 测试助手服务接入测试 Gateway。
2. Tool Adapter 对接测试 Java API 或受控联调接口。
3. 助手库表、Redis、可观测、大模型全部使用测试环境。
4. 对生产正式接口联调时，只允许通过受控白名单方式进行。

### 阶段 3：生产试点

目标：在小范围用户和低风险场景中试点。

部署方式：

1. 生产环境部署数据资产助手服务。
2. 通过生产 Gateway 获取 Token 并透传用户身份。
3. Tool Adapter 调用生产核心网 Java API。
4. 接入生产大模型和生产可观测平台。
5. 写操作走 Activiti 流程和用户二次确认。

### 阶段 4：规模化推广

目标：覆盖更多数据资产子 Agent 和治理场景。

演进方向：

1. 将稳定 Tool 沉淀为标准工具目录。
2. 将复杂领域能力沉淀为 Skill。
3. 将跨系统、跨团队复用能力逐步演进为 MCP 服务。
4. 增加多环境灰度、限流、熔断、审计、评估数据集和回归测试。
