# 99 附录 架构图绘制规则

## 1. 适用范围

本文档用于规范数据资产助手相关架构图的绘制方式，尤其适用于 draw.io 正式评审图。

适用图类型：

1. 应用架构图。
2. 技术架构图。
3. 数据流向图。
4. Agent 编排图。
5. Demo 与生产差异图。
6. 部署架构图。

## 2. 颜色规范

延续前面资产盘点图的颜色含义，不同颜色代表不同状态。

| 状态 | 填充色 | 边框色 | 使用场景 |
| --- | --- | --- | --- |
| 已有能力 | `#E9F7EF` | `#4FA36D` | 现有 Gateway、Java API、ES、Activiti、平台审计、现有前端 |
| 本期新增 | `#EAF2FF` | `#6D99D4` | FastAPI、LangGraph、子 Agent、Tool Adapter、新增助手服务 |
| Demo Mock | `#FFF9E7` | `#D99525` | Gateway Mock、Mock Tool、Mock 数据、模拟流程实例 |
| 后续演进 | `#F2ECFF` | `#7E65C7` | Skill、MCP、后续平台化能力 |
| 状态/观测 | `#FFF3E6` | `#D97822` | Redis、GoldenDB 助手库表、OpenTelemetry、Langfuse |
| 普通说明 | `#FFFFFF` | `#D8DDE5` | 说明框、原则、备注 |

## 3. 连线规范

### 3.1 核心原则

1. 线不要穿越模块。
2. 线不要交叉。
3. 主链路只画相邻模块之间的连线。
4. 状态、观测、审计、Mock 等旁路关系也要用连接线表达，但连线必须走空白通道。
5. 复杂关系宁可拆成多张图，也不要在一张图里堆满连线。

### 3.2 主链路画法

主业务链路建议从左到右水平展开：

```text
用户入口
  -> Gateway
  -> FastAPI
  -> LangGraph
  -> 子 Agent
  -> Tool Adapter
  -> 现有平台能力
```

主链路线条建议：

| 类型 | 样式 |
| --- | --- |
| 主链路 | 蓝色实线，线宽 3，箭头向右 |
| Demo 替代链路 | 黄色虚线，线宽 2 |
| 调用大模型 | 橙色虚线，线宽 2 |
| 内部短连接 | 同色虚线，必须在同一分组内完成 |

### 3.3 旁路关系画法

以下关系需要画连接线，但不要穿越模块：

1. FastAPI 到 Redis。
2. FastAPI 到 OpenTelemetry。
3. LangGraph 到 GoldenDB。
4. LLM 到 Langfuse。
5. Tool Adapter 到审计。
6. 现有平台能力到底层业务库。

推荐走线方式：

```text
从源模块边缘出线
  -> 进入模块之间的空白通道
  -> 在泳道之间的留白区域横向或纵向转折
  -> 从目标模块边缘入线
```

示例：

| 关系 | 走线建议 |
| --- | --- |
| FastAPI -> Redis | 从 FastAPI 底部向下，直接进入下方 Redis，不经过其他模块 |
| FastAPI -> OpenTelemetry | 从 FastAPI 底部向下，到泳道间留白后横向转折，再进入 OpenTelemetry |
| LangGraph -> GoldenDB | 避开大模型模块，从 LangGraph 左侧空白通道绕下去 |
| LLM -> Langfuse | 从大模型底部向下，到泳道间留白后横向转折 |
| Tool Adapter -> 审计 | 避开 Mock Tool，从 Tool 左侧空白通道下行，再转入审计 |
| 平台能力 -> Oracle / GoldenDB | 从平台能力底部垂直下行，连接底层业务库 |

编号或文字标签只能作为辅助说明，不能替代连接线。

## 4. 布局规范

### 4.1 推荐布局

正式应用架构图建议采用两段式布局：

```text
上半部分：主业务调用链路
下半部分：状态、数据、观测、审计旁路
```

布局要求：

1. 上方主链路从左到右。
2. 下方状态/观测模块按对应主链路模块大致垂直对齐。
3. Demo Mock 放在对应真实模块下方或旁边，连接线也必须走空白区域。
4. 图例放在右上角。
5. 落地原则放在底部说明框。

### 4.2 模块数量控制

一张正式架构图里，主链路模块建议不超过 7 个：

1. 用户入口层。
2. 平台接入层。
3. AI 助手服务层。
4. Agent 编排层。
5. 领域子 Agent 层。
6. Tool Adapter 层。
7. 现有平台能力层。

如果子 Agent 或 Tool 太多，用分组框或列表表达，不逐个拉线。

### 4.3 部署架构图布局

部署架构图用于表达服务部署位置、网络边界、生产 / 测试环境隔离、以及外部能力分环境对接。

推荐采用上下泳道布局：

```text
上方：测试环境 / Demo 与联调区
下方：生产环境 / 正式运行区
生产环境内部单独标出：核心网正式接口区
```

部署架构图必须体现：

1. 测试环境和生产环境分开画，不要混在同一条链路中。
2. 生产正式接口位于生产环境核心网。
3. 测试环境默认只用于测试和联调，默认不直连生产正式接口。
4. 大模型需要分测试大模型、生产大模型。
5. 可观测平台需要分测试 OpenTelemetry / Langfuse、生产 OpenTelemetry / Langfuse。
6. Redis、助手库表、模型地址、观测项目、密钥、Gateway 地址均需要分环境隔离。
7. 如需表达测试到生产的发布关系，只画制品或配置晋级线，不画测试数据复制到生产。

部署架构图主链路建议：

```text
测试用户 -> Gateway Mock / 测试 Gateway -> 助手测试服务 -> Mock Tool / 测试 Tool -> 测试接口 / Mock 数据

正式用户 -> 生产 Gateway -> 助手生产服务 -> 生产 Tool Adapter -> 生产 Java API -> ES / Activiti / Oracle / GoldenDB
```

生产核心网建议用醒目的分组框表达，核心网内放置生产 Java API、ES、Activiti、Oracle / GoldenDB 等正式能力。

## 5. draw.io 样式建议

### 5.1 基础样式

节点建议使用直角矩形：

```text
rounded=0;whiteSpace=wrap;html=1;
```

泳道建议使用：

```text
swimlane;html=1;rounded=0;startSize=34;
```

主链路边建议使用：

```text
edgeStyle=orthogonalEdgeStyle;rounded=0;strokeColor=#356FCA;strokeWidth=3;endArrow=block;endFill=1;
```

Demo 虚线建议使用：

```text
edgeStyle=orthogonalEdgeStyle;rounded=0;strokeColor=#D99525;strokeWidth=2;dashed=1;endArrow=block;endFill=1;
```

### 5.2 图形语义

基础设施和中间件建议使用贴近工程语义的图形，不要全部画成普通矩形。

| 对象 | 推荐图形 | 说明 |
| --- | --- | --- |
| GoldenDB / Oracle | 数据库圆柱图形 | 表达关系型数据库或平台业务库 |
| Redis | 清晰可读的基础图形，优先圆柱或带“缓存中间件”标注的矩形 | 表达缓存、短期会话运行态、待确认状态；不要使用打开后不清楚的云厂商复杂图标 |
| OpenTelemetry / Langfuse | 普通矩形或观测组件框 | 表达旁路观测能力 |
| Activiti | 流程引擎组件框 | 表达审批、流程实例、待办 |
| Java API / Gateway | 已有能力矩形 | 表达平台已有服务 |

应用框架必须明确表达：

| 框架 | 图中表达方式 | 职责 |
| --- | --- | --- |
| LangGraph | Agent 编排层核心框 | Router、Planner、Executor、人工确认、状态恢复 |
| LangChain Core | LangGraph 下方或旁边的框架能力框 | Prompt Template、Runnable、Tool Calling 适配、模型调用封装 |

不要只在说明文字里提 LangGraph / LangChain，正式应用架构图中应有明确节点或在核心节点中明确标注。

## 6. 检查清单

出图前逐项检查：

1. 是否有线穿越模块。
2. 是否有线交叉。
3. 是否存在用编号替代连接线的问题。
4. 跨层线是否走空白通道。
5. 主链路是否从左到右清晰可读。
6. 不同状态的颜色是否和图例一致。
7. Mock 能力是否用黄色表达。
8. 新增能力是否用蓝色表达。
9. 已有能力是否用绿色表达。
10. 状态/观测是否放在旁路，不干扰主链路。
11. 是否能一眼看出生产链路和 Demo 链路差异。
12. 是否保留了 Markdown 版本作为源码说明。
